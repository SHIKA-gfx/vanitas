# 008. 부가기능 허브와 스토리 길잡이

> 작성: 2026-11-16 · 상태: 설계 확정(이 문서) → 새 판 감지 → 허브 → 스토리 데이터 틀 → 로직 → 화면 → `v0.4.0`
> 관련: `docs/006`(DB·관리자, 6-3-3 데이터 문서 편집), `docs/007`(로그인 저장, 10-4 옛 탭), `src/lib/state/`(브라우저 저장), `vanitas-design.md`(5-19 누름 효과·모션 규칙)
> 기한: 기말 발표 **2026-12-07**. **12-01 전후 기능 동결**, 마지막 주는 발표 준비·안정화.

## 1. 무엇을 하는가

계산기·플래너와 별개인 서브 콘텐츠를 더한다. 몰루로그 등 기존 도구에 없는 것으로 고른다 (2026-11-16).

- **부가기능 허브** `/extra`: 홈 가운데 원형 VANITAS 로고를 누르면 열리는 페이지. 서브 콘텐츠를 카드로 모아 둔다. 콘텐츠를 더할 때는 등록부(`src/lib/extras.ts`)에 한 줄 + 라우트 폴더 하나
- **스토리 길잡이** `/extra/story`: "어디까지 봤는지"를 정하면, 그 지점까지 밝혀진 내용만 보여 주는 **스포일러 안전 스토리 안내**
  - 메인·이벤트 스토리의 **공개 순서와 작중 시간 순서가 다르다**는 혼란을 푼다 (운영자 본인이 나무위키를 보며 겪은 문제)
- **학생이랑 더 친해지기**(일일 학생 맞히기): 스토리 길잡이 동결 뒤에 설계한다. **완성 전에는 허브에 보이지 않는다** (D9)

### 1-1. MVP (12-01까지)

스토리 길잡이를 두 부분으로 나눈다. 콘텐츠 비용이 다르기 때문이다.

| 부분 | 내용 | 콘텐츠 비용 | MVP 범위 |
|---|---|---|---|
| **A. 읽는 순서 지도** | 스토리 단위(장·이벤트) 목록. 공개순 ↔ 작중순 전환, 읽음 체크, "먼저 읽으면 좋은 스토리" | 낮음 (제목·날짜·순서·근거) | **메인 전 권 + 이벤트 스토리 전부** |
| **B. 스포일러 안전 사전** | 인물·조직·장소·용어. 읽은 범위까지만 설명이 열린다 | 높음 (직접 써야 함) | **메인 Vol.1 범위, 20~30항목** (D3) |

콘텐츠 입력이 가장 큰 위험이다 — **A를 먼저 다 넣고**, B는 남는 시간만큼. B가 적어도 A만으로 원래 고민은 풀린다.

### 1-2. 하지 않는 것 (MVP 밖)

- 인연·그룹·미니 스토리 — 단위 수가 많다. 데이터의 `kind`로 자리만 열어 둔다
- 일본어판 콘텐츠 — UI 문구만 Paraglide, 콘텐츠는 한국어만
- 줄거리 요약 — 분량·저작권 부담. 사전 설명까지만
- 게임 이미지·대사 인용 — 넥슨 IP 가이드 문의 답변 전 (7장)
- 사전 항목 상세 페이지 (D7) — 발표 뒤
- 진행도 공유 링크 — 남의 진행도로 보면 스포일러가 된다

## 3. 먼저: 새 판 감지·탭 사이 저장 (2026-11-16)

스토리 진행도는 저장 파일의 **새 묶음 `story`**다 (9장). 그 전에 저장이 지워지는 두 경로를 막는다.

| 경로 | 전에는 | 이제 |
|---|---|---|
| **탭 사이** | 탭마다 처음 읽은 저장 파일 사본을 들고 있다가, 쓸 때 **파일 전체를 그 사본으로** 덮었다. 플래너 탭을 연 채 다른 탭에서 진행도를 정하면, 플래너를 고칠 때 진행도가 지워지고 계정에도 그렇게 올라갔다 (같은 판끼리도 일어난다) | `SavedStore.write`·`exportFile`이 **쓸·내보낼 때마다 저장소를 다시 읽어** 그 묶음만 바꾼다. 같은 묶음을 두 탭에서 고치면 나중에 쓴 쪽이 남는다 |
| **옛 탭** (`docs/007` 10-4) | 배포 전부터 열린 탭은 새 칸을 모른다. `sanitize`가 모르는 칸을 버리고 묶음을 통째로 써서 계정까지 올라갔다 | **새 판 감지**: SvelteKit `version.pollInterval`(10분) + 탭으로 돌아올 때 `updated.check()`. 새 판이면 다른 화면으로 옮길 때 새로 고침으로 옮기고, 같은 화면에 머물면 띠로 권한다 (`UpdateBar.svelte`) |

- 새 판 = 새 빌드. **관리자 데이터 저장으로 다시 배포해도 새 판**이다(판 이름은 빌드 시각) — 바뀐 데이터를 보라는 뜻이라 맞다
- 띠 문구: "VANITAS가 새로 바뀌었어요. 새로 고침하면 바뀐 데이터와 기능으로 볼 수 있어요." [나중에] [새로 고침]. "나중에"는 그 탭에서 다시 띄우지 않는다
- 공유 링크를 보는 동안·관리자 페이지에서는 띄우지도 새로 고치지도 않는다 (공유 보기가 풀리지 않게, 고치던 문서를 잃지 않게. 관리자 페이지는 저장할 때마다 배포가 일어난다)
- 입력은 브라우저에 바로 저장되므로 새로 고쳐도 잃지 않는다
- **이 감지는 이 코드가 배포된 뒤 연 탭부터 동작한다** → 스토리 화면(새 묶음 `story`)보다 며칠 먼저 배포한다
- 계정 올리기를 새 판일 때 멈추지는 않는다 — 탭 사이 저장으로 새 *묶음*은 지워지지 않고, 묶음 안의 새 *칸*은 새로 고침 권하기로 충분하다고 본다

## 4. 허브

### 4-1. 주소

| 주소 | 화면 |

### 4-2. 들어가는 길

- **데스크톱**: `HomeFrame.svelte` 가운데 원(로고)을 `<a>`로. `aria-label`("부가기능"), 키보드 포커스 링, hover·누름 상태(디자인 5-19 누름 효과). 원 아래 라벨 "부가기능 ›" (D2-b)
  - 모션 규칙(상태 변화만)에 맞춘다 — 장식 애니메이션 없음
- **모바일**: 홈 1열 맨 아래, 백업 링크 위에 "부가기능" 카드 한 줄 (D2)

### 4-3. 등록부

게임 규칙 값이 아니라 사이트 구성이므로 코드에 둔다.

```ts
// src/lib/extras.ts
export interface Extra {
  id: 'story';               // 콘텐츠를 더할 때 늘린다
  path: '/extra/story';
  title: () => string;       // Paraglide 메시지
  summary: () => string;
}
export const extras: Extra[] = [ /* story 하나 (D9) */ ];
```

- 허브 페이지는 이 배열만 그린다
- 카드가 하나뿐이어도 허브를 거친다 — 콘텐츠가 늘어도 들어가는 길이 바뀌지 않게

## 5. 스토리 길잡이 화면

```
[진행도 판]  메인 스토리: [Vol.▾] [장▾] 까지 봤어요   이벤트 스토리: N개 읽음 (읽는 순서 탭에서 체크)
[탭]  읽는 순서 | 사전
─ 읽는 순서 ─
  정렬: (공개순) (작중순)
  카드: 제목 · 종류 배지(메인/이벤트) · 한국 공개일 · 작중 위치 메모 · 확실성("추정") · "먼저 읽으면 좋아요: …" · [읽음 ☐]
  작중순에서 시점 미확인 단위는 맨 아래 "작중 시점 미확인" 묶음
─ 사전 ─
  검색 + 종류 필터(인물/조직/장소/용어)
  항목: 이름 + 읽은 범위까지 열린 설명 블록들 (목록 안에서 펼침, D7)
  아직 등장 전인 항목은 목록에 나오지 않는다. 숨은 블록 수는 알리지 않는다 (D6)
```

- **첫 방문(진행도 없음)**: 사전 내용은 아무것도 보이지 않고 진행도 설정만. "아무것도 안 봤어요"도 선택지
- 페이지 아래에 "비공식 팬 콘텐츠, 설명은 운영자가 직접 작성" 고지 (7장)
- 화면을 바꾸면 375px·1280px 캡처

## 6. 데이터 (`data/ko/story.json`, D4)

### 6-1. 원칙

- 게임 데이터와 같은 길: **DB `datasets`의 문서가 정본**, 관리자 "문서" 탭에서 고침 → 재배포, 빌드 때 `data/ko/story.json`으로 내려받고 `validate.py`로 검사
- 순서·공개일·선행 관계는 **사실 정보 + 출처 + 확실성**. 확실하지 않으면 `inferred`, 화면에 "추정"
- 사전 설명은 **운영자가 직접 쓴 글** (7장)

### 6-2. 문서 모양

```ts
interface StoryDoc {
  meta: { description: string; verifiedAt: string; sources: string[] }; // 다른 문서와 같은 meta
  units: StoryUnit[];
  entries: StoryEntry[];
}

type UnitId = string; // 'main-v1-c1', 'event-<slug>'

interface StoryUnit {
  id: UnitId;
  kind: 'main' | 'event';             // 이후 'bond' 등을 더할 자리
  title: string;                      // 한국 서버 표기
  volume?: string;                    // main만: 권 id ('v1', 'final' 등)
  chapter?: number;                   // main만: 권 안의 장 번호 (진행도 단위, D5)
  releasedKr?: string;                // YYYY-MM-DD, 한국 서버 첫 공개일 (복각 아님)
  mainOrder?: number;                 // main만: 메인 진행 순서 (진행도 포인터)
  chrono?: {
    key: number;                      // 작중 시간 정렬 키 (100 단위로 띄워 끼워 넣기 쉽게). 날짜를 지어내지 않는다
    note?: string;                    // "Vol.3 2장과 3장 사이"
    certainty: 'stated' | 'inferred'; // stated = 게임 안·공지로 확인
    sources: string[];
  };
  readAfter?: UnitId[];               // "먼저 읽으면 좋아요". 근거 필요
  readAfterSources?: string[];
  replayable?: 'yes' | 'no' | 'unknown'; // 지금 게임에서 다시 볼 수 있는지 — 검증 전에는 unknown
  sources: string[];
  verified: boolean;
}

interface StoryEntry {
  id: string;
  kind: 'person' | 'group' | 'place' | 'term';
  firstAppears: UnitId;               // 이 단위를 읽기 전에는 목록에도 없다
  blocks: {
    after: UnitId;                    // 이 단위를 읽었으면 보인다
    name?: string;                    // 이름 자체가 스포일러면 블록별로 바꾼다
    text: string;                     // 직접 쓴 설명. 대사 인용 금지
  }[];                                // 덮어쓰기가 아니라 덧붙이기. 첫 블록 after === firstAppears, 첫 블록은 name 필수
  related?: string[];                 // 상대 항목이 보일 때만 링크
  sources: string[];
  verified: boolean;
}
```

- `chrono`가 없는 단위 = "작중 시점 미확인" 묶음
- 이벤트는 순서 없이 읽으므로 블록마다 조건을 따로 두고, 조건을 만족한 블록을 모두 보인다

### 6-3. DB에 넣기

- `datasets.path` 검사(`^(sources\.json|(shared|ko|ja)/[a-z0-9-]+\.json)$`)는 `ko/story.json`을 이미 받는다. 표로 뺄 자리가 없어 검사 제약은 그대로
- **`save_dataset`은 새 문서를 더하지 않는다**(`docs/006` 6-3-3) → 새 마이그레이션이 `ko/story.json` 행을 넣는다 (`meta` + 빈 `units`·`entries`)
- **빌드의 내보내기는 레포 `data/`와 DB `datasets`의 파일 목록이 다르면 멈춘다** (`scripts/data-export.ts`). 그래서:
  - 순서: PR이 준비되면 **마이그레이션을 SQL Editor로 실행 → 바로 Merge**. 그사이 관리자 저장(재배포)은 하지 않는다 — 운영 사이트는 실패한 빌드 전 배포에 남는다(`docs/006` 6-4)
  - PR 미리보기 빌드는 마이그레이션 전에 실패한다 → 실행 뒤 다시 돌린다
- 관리자 "문서" 탭: `doc-sections.ts`에 묶음 "스토리 길잡이"(`units`·`entries`, `meta`는 "문서 정보"), `DocPath`·`SITE_FILES`에 `ko/story.json`. 긴 설명을 칸으로 고치기 불편하면 JSON 원문으로 — 데이터 틀 단계에서 실제로 써 보고 정한다
- 사이트는 스토리 화면에서만 `story.json`을 읽는다 (다른 화면 번들에 넣지 않는다)

### 6-4. `validate.py` 검사

- id 중복 없음, `readAfter`·`related`·`after`·`firstAppears`가 실제 id를 가리킴
- `main`은 `volume`·`chapter`·`mainOrder` 필수, `mainOrder` 중복 없음
- `readAfter`가 순환하지 않음
- 각 항목의 첫 블록 `after === firstAppears`, 첫 블록에 `name`
- `chrono.certainty === 'stated'`이면 `chrono.sources` 비어 있지 않음
- `sources` id가 `sources.json`에 있음
- 관리자 화면의 저장 전 검사는 같은 `validate.py`를 브라우저에서 돌리므로(`build-check.ts`) 따로 옮기지 않는다

## 7. 저작권·IP (화면 "정보와 출처"에도)

- 게임 이미지·일러스트·음악·대사 인용을 쓰지 않는다
- **나무위키 문장을 옮기지 않는다.** 나무위키는 CC BY-NC-SA 2.0 KR이라 VANITAS 데이터 라이선스(CC BY 4.0)와 섞을 수 없다. 사실 확인용으로만 보고 설명은 직접 쓴다
- 공개일·순서 같은 사실 정보는 출처를 `sources.json`에 (공식 공지 = `official`, 커뮤니티 = `community`)
- 페이지 아래 "비공식 팬 콘텐츠, 설명은 운영자가 직접 작성" 고지

## 8. 로직 (`src/lib/story/`, 순수 TS, 테스트 먼저)

```ts
// 읽은 단위 집합: 메인 포인터 이하 전부 + 읽은 이벤트
export function readSet(units: StoryUnit[], save: StorySave): Set<UnitId>;

// 항목이 보이는지, 보이는 블록, 보일 이름(열린 블록 중 마지막 name)
export function visibleEntry(entry: StoryEntry, read: Set<UnitId>):
  { name: string; blocks: { text: string }[] } | null;

// release = releasedKr 오름차순(같으면 mainOrder), chrono = chrono.key 오름차순, 키 없음은 따로
export function orderUnits(units: StoryUnit[], by: 'release' | 'chrono'):
  { ordered: StoryUnit[]; unknown: StoryUnit[] };
```

- 블록 "가장 최근" = 블록 배열 순서 (작성자가 이야기 진행 순으로 쓴다)
- 테스트는 실제 `data/ko/story.json` 스냅샷 + 내용이 적은 초기에는 작은 고정 데이터도
- `.svelte.ts`에서 `Set`을 바꾸면 `svelte/prefer-svelte-reactivity` — 읽은 집합은 매번 새로 만든다

### 8-1. 스포일러가 HTML에 새지 않게

- 진행도는 브라우저에만 있어 빌드는 무엇을 보일지 모른다 → 사전 블록은 **클라이언트에서 진행도를 읽은 뒤에만** 그린다. 미리 렌더된 HTML에는 진행도 판과 단위 목록(제목·날짜)만
- 데이터 JSON 자체는 번들에서 읽을 수 있다 — 보안이 아니라 "실수로 보지 않게"가 목표이므로 받아들인다

## 9. 저장 (`sections.story`)

```ts
interface StorySave {
  mainUpTo: UnitId | null;      // 메인 스토리 어디까지 (장 단위, D5). null = 아직 안 봄
  readEvents: UnitId[];         // 읽은 이벤트 스토리
  order: 'release' | 'chrono';  // 마지막으로 본 정렬
}
```

- **새 묶음**이다. 판 번호를 올리지 않는다 — 없으면 `sanitize`가 기본값으로 채운다 (기존 규칙)
- 로그인 저장(`user_saves`, 64KB)으로 기기끼리 맞춰진다. 이벤트 id 수백 개여도 용량 문제 없음
- 공유 링크·백업: 백업 링크에는 묶음 전체가 들어간다. **공유 링크(결과 공유)에는 넣지 않는다** (1-2)
- 탭 사이·옛 탭 문제는 3장에서 먼저 막는다
