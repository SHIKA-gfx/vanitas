# 008. 부가기능 허브와 스토리 길잡이

> 작성: 2026-11-16 · 상태: 설계 확정(#97) → 새 판 감지(#98) → 허브(#99, 4장) → **스토리 데이터 틀(이 PR, 6장)** → 로직 → 화면 → `v0.4.0`
> 관련: `docs/006`(DB·관리자, 6-3-3 데이터 문서 편집), `docs/007`(로그인 저장, 10-4 옛 탭), `src/lib/state/`(브라우저 저장), `vanitas-design.md`(5-19 누름 효과·모션 규칙)
> 기한: 기말 발표 **2026-12-07**. **12-01 전후 기능 동결**, 마지막 주는 발표 준비·안정화.

## 1. 무엇을 하는가

계산기·플래너와 별개인 서브 콘텐츠를 더한다. 몰루로그 등 기존 도구에 없는 것으로 고른다 (2026-11-16).

- **부가기능 허브** `/extra`: 홈 가운데 원형 VANITAS 로고를 누르면 열리는 페이지. 서브 콘텐츠를 카드로 모아 둔다. 콘텐츠를 더할 때는 등록부(`src/lib/extras.ts`)에 한 줄 + 라우트 폴더 하나
- **스토리 길잡이** `/extra/story`: "어디까지 봤는지"를 정하면, 그 지점까지 밝혀진 내용만 보여 주는 **스포일러 안전 스토리 안내**
  - 메인·이벤트 스토리의 **공개 순서와 작중 시간 순서가 다르다**는 혼란을 푼다 (운영자 본인이 나무위키를 보며 겪은 문제)
- **학생이랑 더 친해지기**(일일 학생 맞히기): 스토리 길잡이 동결 뒤에 설계한다. **완성 전에는 허브에 보이지 않는다** (D9)

### 1-1. MVP (12-01까지)

스토리 길잡이를 두 부분으로 나눈다. 콘텐츠 비용이 다르기 때문이다.

| 부분 | 내용 | 콘텐츠 비용 | MVP 범위 |
|---|---|---|---|
| **A. 읽는 순서 지도** | 스토리 단위(장·이벤트) 목록. 공개순 ↔ 작중순 전환, 읽음 체크, "먼저 읽으면 좋은 스토리" | 낮음 (제목·날짜·순서·근거) | **메인 전 권 + 이벤트 스토리 전부** |
| **B. 스포일러 안전 사전** | 인물·조직·장소·용어. 읽은 범위까지만 설명이 열린다 | 높음 (직접 써야 함) | **메인 Vol.1 범위, 20~30항목** (D3) |

콘텐츠 입력이 가장 큰 위험이다 — **A를 먼저 다 넣고**, B는 남는 시간만큼. B가 적어도 A만으로 원래 고민은 풀린다.

### 1-2. 하지 않는 것 (MVP 밖)

- 인연·그룹·미니 스토리 — 단위 수가 많다. 더할 때는 `main`·`events`처럼 목록을 하나 더 둔다 (6-2)
- 일본어판 콘텐츠 — UI 문구만 Paraglide, 콘텐츠는 한국어만
- 줄거리 요약 — 분량·저작권 부담. 사전 설명까지만
- 게임 이미지·대사 인용 — 넥슨 IP 가이드 문의 답변 전 (7장)
- 사전 항목 상세 페이지 (D7) — 발표 뒤
- 진행도 공유 링크 — 남의 진행도로 보면 스포일러가 된다

## 3. 먼저: 새 판 감지·탭 사이 저장 (2026-11-16)

스토리 진행도는 저장 파일의 **새 묶음 `story`**다 (9장). 그 전에 저장이 지워지는 두 경로를 막는다.

| 경로 | 전에는 | 이제 |
|---|---|---|
| **탭 사이** | 탭마다 처음 읽은 저장 파일 사본을 들고 있다가, 쓸 때 **파일 전체를 그 사본으로** 덮었다. 플래너 탭을 연 채 다른 탭에서 진행도를 정하면, 플래너를 고칠 때 진행도가 지워지고 계정에도 그렇게 올라갔다 (같은 판끼리도 일어난다) | `SavedStore.write`·`exportFile`이 **쓸·내보낼 때마다 저장소를 다시 읽어** 그 묶음만 바꾼다. 같은 묶음을 두 탭에서 고치면 나중에 쓴 쪽이 남는다 |
| **옛 탭** (`docs/007` 10-4) | 배포 전부터 열린 탭은 새 칸을 모른다. `sanitize`가 모르는 칸을 버리고 묶음을 통째로 써서 계정까지 올라갔다 | **새 판 감지**: SvelteKit `version.pollInterval`(10분) + 탭으로 돌아올 때 `updated.check()`. 새 판이면 다른 화면으로 옮길 때 새로 고침으로 옮기고, 같은 화면에 머물면 띠로 권한다 (`UpdateBar.svelte`) |

- 새 판 = 새 빌드. **관리자 데이터 저장으로 다시 배포해도 새 판**이다(판 이름은 빌드 시각) — 바뀐 데이터를 보라는 뜻이라 맞다
- 띠 문구: "VANITAS가 새로 바뀌었어요. 새로 고침하면 바뀐 데이터와 기능으로 볼 수 있어요." [나중에] [새로 고침]. "나중에"는 그 탭에서 다시 띄우지 않는다
- 공유 링크를 보는 동안·관리자 페이지에서는 띄우지도 새로 고치지도 않는다 (공유 보기가 풀리지 않게, 고치던 문서를 잃지 않게. 관리자 페이지는 저장할 때마다 배포가 일어난다)
- 입력은 브라우저에 바로 저장되므로 새로 고쳐도 잃지 않는다
- **이 감지는 이 코드가 배포된 뒤 연 탭부터 동작한다** → 스토리 화면(새 묶음 `story`)보다 며칠 먼저 배포한다
- 계정 올리기를 새 판일 때 멈추지는 않는다 — 탭 사이 저장으로 새 *묶음*은 지워지지 않고, 묶음 안의 새 *칸*은 새로 고침 권하기로 충분하다고 본다

## 4. 허브

### 4-1. 주소

| 주소 | 화면 |
|---|---|
| `/ko/extra` | 부가기능 허브 (카드 목록) |
| `/ko/extra/story` | 스토리 길잡이 |

- 로케일은 기존처럼 reroute. 링크는 `resolve()` (ESLint `svelte/no-navigation-without-resolve`)
- `static/sitemap.xml`(손으로 관리): `/ko/extra`는 허브 PR에서, `/ko/extra/story`는 스토리 화면 PR에서 더한다 (없는 주소를 알리지 않게)
- 넓은 화면 왼쪽 목록·모바일 탭바에는 넣지 않는다 — 계산기 네 자리 그대로. 허브에서 홈으로는 오른쪽 위 홈 원으로

### 4-2. 들어가는 길

- **데스크톱**(`md` 이상, 가운데 원이 보이는 폭): `HomeFrame.svelte` 가운데 원을 타일처럼 **SVG 안의 `<a>`**로 감싼다 — 누르는 영역·초점 테두리가 원 모양을 따른다
  - `aria-label` "부가기능". 키보드 초점: 원과 틈 사이에 `brand-strong` 3px 테두리(타일 초점 테두리와 같은 굵기·색) + 뒤 번짐이 짙어짐(45% → 80%)
  - 마우스를 올리면 뒤 번짐만 짙어진다. 누름 효과는 사이트 공통(링크 전부). 장식 움직임 없음 (5-18)
  - **라벨 "부가기능 ›"는 원 안, 워드마크 아래 흰 알약** (D2-b를 구현하며 정함): 원 바로 아래는 아래 타일의 곡선이 닿아 자리가 없다.
    흰 바탕(`surface` 94%) + `brand-strong` 굵은 14px — 작은 글자도 4.5:1 이상. 링크 이름과 두 번 읽히지 않게 낭독에서 숨긴다
- **모바일**(`md` 미만): 계산기 타일 아래, 계정·백업 묶음 위에 **낮은 한 줄 카드** (D2) — 반짝임 아이콘 + "부가기능" + 허브의 콘텐츠 이름들(` · `로 이음, 넘치면 말줄임) + `›`.
  계산기 타일(96px, 흰색)과 구분되게 56px·흰색 70%(데스크톱 타일의 쉬는 상태와 같은 농도), 누르면 흰색

### 4-3. 등록부

게임 규칙 값이 아니라 사이트 구성이므로 코드에 둔다.

```ts
// src/lib/extras.ts
export interface Extra {
  id: 'story';               // 콘텐츠를 더할 때 늘린다. 통계 extra-open의 id
  path: string;              // `/extra/<id>` (extras.test.ts가 지킨다)
  title: () => string;       // Paraglide 메시지
  summary: () => string;
  icon: NavIconName;
  ready: boolean;            // false면 "준비 중" 카드, 링크 없음 (nav.ts와 같은 방식)
}
export const extras: Extra[] = [ /* story 하나 (D9) */ ];
```

- 허브 페이지와 모바일 홈 카드가 이 배열을 그린다. 아직 보이지 않게 할 콘텐츠는 배열에 넣지 않는다 (D9)
- **스토리 길잡이는 화면이 들어오는 PR까지 `ready: false`** — 허브가 먼저 배포되므로 없는 화면으로 링크하지 않는다. `extras.test.ts`가 준비된 콘텐츠의 화면 파일이 있는지 본다
- 카드가 하나뿐이어도 허브를 거친다 — 콘텐츠가 늘어도 들어가는 길이 바뀌지 않게

### 4-4. 허브 화면 (`src/routes/extra/+page.svelte`)

- 제목 줄 `PageTitle`(아이콘 칩 `extra`) + 소개 한 줄("계산기와 따로 즐길 거리를 모아 뒀어요.", `navy` — 배경 위 글자 규칙)
- 카드는 모바일 홈 타일과 같은 모양(96px, 흰 판, 아이콘 28px + 제목 + 설명 한 줄). 준비 중은 점선 + "준비 중" 배지. 넓은 화면도 한 열(최대 672px)
- 카드를 누르면 `extra-open`(`id`) (10장)

### 4-5. 아이콘 (디자인 문서 6장에 더함)

| 화면 | 아이콘 | `name` |
|---|---|---|
| 부가기능 | 네 갈래 반짝임 (곡선으로 파인 별) | `extra` |
| 스토리 길잡이 | 펼친 책 | `story` |

- 기존 규칙 그대로: 24px 격자·선 굵기 2·정수 좌표·둥근 끝. `vt-icon-extra`(모바일 홈 카드 ↔ 허브 제목 칩), `vt-icon-story`(허브 카드 ↔ 스토리 제목 칩)로 화면 전환 때 짝지어진다

## 5. 스토리 길잡이 화면

```
[진행도 판]  메인 스토리: [Vol.▾] [장▾] 까지 봤어요   이벤트 스토리: N개 읽음 (읽는 순서 탭에서 체크)
[탭]  읽는 순서 | 사전
─ 읽는 순서 ─
  정렬: (공개순) (작중순)
  카드: 제목 · 종류 배지(메인/이벤트) · 한국 공개일 · 작중 위치 메모 · 확실성("추정") · "먼저 읽으면 좋아요: …" · [읽음 ☐]
  작중순에서 시점 미확인 단위는 맨 아래 "작중 시점 미확인" 묶음
─ 사전 ─
  검색 + 종류 필터(인물/조직/장소/용어)
  항목: 이름 + 읽은 범위까지 열린 설명 블록들 (목록 안에서 펼침, D7)
  아직 등장 전인 항목은 목록에 나오지 않는다. 숨은 블록 수는 알리지 않는다 (D6)
```

- **첫 방문(진행도 없음)**: 사전 내용은 아무것도 보이지 않고 진행도 설정만. "아무것도 안 봤어요"도 선택지
- 페이지 아래에 "비공식 팬 콘텐츠, 설명은 운영자가 직접 작성" 고지 (7장)
- 화면을 바꾸면 375px·1280px 캡처

## 6. 데이터 (`data/ko/story.json`, D4)

### 6-1. 원칙

- 게임 데이터와 같은 길: **DB `datasets`의 문서가 정본**, 관리자 "문서" 탭에서 고침 → 재배포, 빌드 때 `data/ko/story.json`으로 내려받고 `validate.py`로 검사
- 순서·공개일·선행 관계는 **사실 정보 + 출처 + 확실성**. 확실하지 않으면 `inferred`, 화면에 "추정"
- 사전 설명은 **운영자가 직접 쓴 글** (7장)

### 6-2. 문서 모양 (`src/lib/story/types.ts`, 2026-11-16 데이터 틀에서 고침)

관리자 화면의 편집기는 **칸을 더하거나 빼지 못하고, 숫자 칸을 비우지 못하고, 줄 더하기는 마지막 줄 복사**다(`docs/006` 6-3-3).
그래서 처음 초안(선택 칸이 있는 `units` 하나)을 아래처럼 바꿨다.

| 초안 | 바꾼 것 | 까닭 |
|---|---|---|
| `units` 하나에 `kind: 'main' \| 'event'` | **목록 넷**: `volumes`(권) · `main`(장) · `events` · `entries` | 종류마다 칸이 달라 한 표에 두면 빈 칸이 생긴다. 메인은 **목록 순서 = 진행 순서**라 `mainOrder`가 없어도 된다 |
| 있을 수도 없을 수도 있는 칸(`chrono?`, `readAfter?` …) | **칸은 늘 모두 있다.** 모르면 빈 글자·빈 목록·`0` | 편집기가 칸을 더하지 못한다 |
| `chrono: { key, note, certainty, sources }` | 평평하게 `chronoKey`·`chronoNote`·`chronoCertainty`(`unknown` 추가)·`chronoSources` | 표 한 줄로 고친다. `unknown`이면 키 `0` → "작중 시점 미확인" 묶음 |
| `kind`(사전 종류) | `entryType` | 편집기의 선택지 표(ENUMS)는 칸 이름으로 찾는다 — `kind`는 다른 문서에도 있다 |
| `firstAppears` + 첫 블록 `after` | **첫 블록의 `after`가 처음 등장** (칸 하나 뺌) | 둘은 늘 같아야 해서 어긋날 일만 생긴다 |
| `name?` (블록) | `name` — 빈 글자 = 이름 그대로 | 칸은 늘 모두 있다 |

```ts
interface StoryDoc {
  meta: { id; server; description; verifiedAt; sources: string[]; notes: string[] }; // notes = 칸 쓰는 법 (관리자 "문서 정보"에 보인다)
  volumes: { id; title; sources: string[]; verified: boolean }[];
  main: {                 // 목록 순서 = 진행 순서. 같은 권은 이어서, 권 안의 장 번호는 늘어난다
    id; title; volume; chapter: number;               // id 예: main-v1-c1
    releasedKr;           // 한국 서버 첫 공개일 YYYY-MM-DD, 모르면 ''
    chronoKey: number;    // 작중 순서 키 (100 단위로 띄운다). 날짜를 지어내지 않는다
    chronoCertainty: 'unknown' | 'stated' | 'inferred';
    chronoNote; chronoSources: string[];
    replayable: 'unknown' | 'yes' | 'no';           // 지금 게임에서 다시 볼 수 있는지 — 확인 전 unknown
    sources: string[]; verified: boolean;
  }[];
  events: {               // main과 같은 칸에서 volume·chapter 대신 readAfter·readAfterSources
    id; title; releasedKr; chronoKey; chronoCertainty; chronoNote; chronoSources;
    readAfter: string[];  // "먼저 읽으면 좋아요" — 메인·이벤트 id
    readAfterSources: string[]; replayable; sources; verified;
  }[];
  entries: {
    id; entryType: 'person' | 'group' | 'place' | 'term';
    blocks: { after; name; text }[];  // 덧붙이는 블록. 첫 블록 after = 처음 등장, 첫 블록 name 필수
    related: string[]; sources: string[]; verified: boolean;
  }[];
}
```

- id는 소문자·숫자·하이픈. **메인·이벤트는 한 이름 공간**(진행도·블록·먼저 읽기가 함께 가리킨다). 저장된 진행도가 가리키므로 만든 뒤 바꾸지 않는다
- 이벤트는 순서 없이 읽으므로 블록마다 조건을 따로 두고, 조건을 만족한 블록을 모두 보인다

### 6-3. DB에 넣기 (`supabase/migrations/20261117000000_story_dataset.sql`)

- `datasets.path` 검사(`^(sources\.json|(shared|ko|ja)/[a-z0-9-]+\.json)$`)는 `ko/story.json`을 이미 받는다. 표로 뺄 자리가 없어 검사 제약은 그대로
- **`save_dataset`은 새 문서를 더하지 않는다**(`docs/006` 6-3-3) → 마이그레이션이 행을 넣는다 (`meta` + 빈 목록 넷, 레포 파일과 같은 값·키 순서). `on conflict do nothing` — 두 번 실행해도 안전.
  SQL Editor로 넣으면 변경 기록의 `actor`가 비어 남는다 (원래 그렇다)
- **빌드의 내보내기는 레포 `data/`와 DB `datasets`의 파일 목록이 다르면 멈춘다** (`scripts/data-export.ts`). 그래서:
  - 순서: PR이 준비되면 **마이그레이션을 SQL Editor로 실행 → 바로 Merge**. 그사이 관리자 저장(재배포)은 하지 않는다 — 운영 사이트는 실패한 빌드 전 배포에 남는다(`docs/006` 6-4)
  - PR 미리보기 빌드는 마이그레이션 전에 실패한다 → 실행 뒤 다시 돌린다
- 사이트는 스토리 화면에서만 `story.json`을 읽는다 (다른 화면 번들에 넣지 않는다)

**관리자 "문서" 탭** (`src/routes/admin/doc-sections.ts`) — 묶음 "스토리 길잡이"(아이콘 `story`): **읽는 순서**(`volumes`·`main`·`events`, 표) / **사전**(`entries`, 카드). `meta`는 "문서 정보"의 "스토리 (story.json)" — 칸 쓰는 법 메모(`notes`)가 거기 보인다.
편집기에 더한 것 (다른 문서에는 영향 없음):

| 무엇 | 어떻게 |
|---|---|
| 빈 목록에 첫 줄 | `ROW_TEMPLATES`("문서 경로:칸") — 빈 목록이면 "＋ 첫 줄 만들기". 문서 경로는 `DocEditor`가 context로 내려 준다. 틀은 `types.ts` 타입으로 칸을 모두 갖춘다 |
| 사전 항목·설명 블록 더하기 | 카드 목록에 틀이 있으면 **"＋ 빈 줄 더하기"** (긴 설명까지 복사되지 않게). 표(권·장·이벤트)는 그대로 마지막 줄 복사 — 권·출처를 다시 적지 않게 |
| 설명 블록 | `CARD_KEYS`(`blocks`) — 표로 보일 수 있어도 카드. 항목을 펼치면 블록도 펼쳐져 있다 |
| 긴 설명 | `LONG_TEXT_KEYS`(`text`) — 비어 있어도 여러 줄 칸, 한 줄을 다 쓴다 |
| 고르는 칸 | `ENUMS`에 `chronoCertainty`·`replayable`·`entryType` (validate.py와 같은 목록) |
| 칸 이름 | 맨 위 칸은 `TOP_LABELS`("메인 스토리 권·장", "이벤트 스토리", "사전 항목"), 그 밖은 `KEY_LABELS` |

### 6-4. `validate.py` `check_story`

- **칸이 모두 있고 형이 맞는가** (글자·정수·참/거짓·글자 목록). 모르는 칸은 경고
- id: 형식, 겹침 (메인·이벤트 한 이름 공간, 권·사전은 따로)
- 메인: 권이 `volumes`에 있음, 장 번호 1부터, **같은 권은 목록에서 이어서**, 권 안에서 장 번호가 늘어남
- 메인·이벤트: 제목, 한국 공개일 형식(또는 빈 글자), 확실성 값 — `unknown`이면 키 `0`, 아니면 키 > 0, `stated`면 작중 순서 출처 필수. 다시 보기 값
- 이벤트: 먼저 읽기가 있는 id·자기 자신 아님·**근거(출처) 필수**·**돌고 돌지 않음**
- 사전: 종류 값, 블록 1개 이상, 블록 `after`가 메인·이벤트 id, 첫 블록 이름, 설명이 빈 글자 아님, 관련 항목이 있는 id·자기 자신 아님
- 모든 출처 id가 `sources.json`에 있음 (`meta.sources` 포함)
- 확인 전(`verified: false`) 줄 수는 경고 한 줄 (`--strict`면 오류)
- 관리자 화면의 저장 전 검사는 같은 `validate.py`를 브라우저에서 돌리므로(`build-check.ts`) 따로 옮기지 않는다. 일부러 틀린 고정 데이터로 25가지 오류가 모두 잡히는 것을 확인했다 (2026-11-16)

### 8-1. 스포일러가 HTML에 새지 않게

- 진행도는 브라우저에만 있어 빌드는 무엇을 보일지 모른다 → 사전 블록은 **클라이언트에서 진행도를 읽은 뒤에만** 그린다. 미리 렌더된 HTML에는 진행도 판과 단위 목록(제목·날짜)만
